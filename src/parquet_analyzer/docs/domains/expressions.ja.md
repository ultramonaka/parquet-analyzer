# 演算式（仮想変数・ユーザー関数・マップ）

> 総括仕様: [overview.ja.md](../overview.ja.md)（共通ルール・用語・旧節番号の対応表）。
> 本書は「要求」→「設計」の順。節番号は旧仕様書の番号をそのまま使っている。

**この分野の範囲**: 変数間演算と式の評価、仮想変数（追加・編集・削除・依存関係）、Δ解析、関数レジストリ、ユーザー関数、マップ（参照テーブル）。

## 要求

#### 5.5 変数間演算
- 四則演算（+, -, ×, ÷, べき乗, 剰余, 切り捨て除算）、絶対値（abs）、平方根（sqrt）に加え、
  三角関数（sin/cos/tan）、指数・対数（exp/log/log10）、丸め（sign/floor/ceil/round）、
  範囲操作（min/max/clip、いずれも要素ごと）、移動平均（rolling_mean）を変数（列）に対して
  適用できる。詳細・対応関数一覧は
  [detailed_specification.ja.md 6章](#6-演算式入力114)。
- 演算結果は新しい仮想変数としてプロット可能な変数リストに追加される。
- 演算変数名が既存の列名と衝突する場合はエラーとし、データの意図しない上書きを防ぐ。
- 対応演算式の入力方法・UIは 11.4 で確定。
- 演算で作成した変数（仮想変数）も、生データではなく**定義式（式の文字列と入力元変数名）**として
  ビューに保存する。ビュー読み込み時に元の列から再計算して復元する。
  理由: 元データが更新された場合も再計算で追従でき、保存ファイルも軽量に保てるため。
- **仮想変数の編集・削除**（2026-09-30追加、ユーザー要望。詳細は
  [detailed_specification.ja.md 18章](#18-仮想変数の編集削除2026-09-30追加ユーザー要望)）:
  変数リストで仮想変数を右クリックすると「式を編集...」「削除」を選べる。ファイル由来の列には
  どちらも表示しない（式ではなく実データのため）。
  - 編集は別ダイアログではなく、追加に使うのと同じ式入力バーで行う: バーが編集モードに
    切り替わり、名前は固定、現在の式が入った状態になる。編集中も変数リストからのドラッグや
    ダブルクリックで変数名を挿入できる。「更新」で適用、「キャンセル」で追加モードに戻る。
  - 編集で変更できるのは式のみで、名前は変わらない（他の式が名前で参照しているため、改名は
    対象外）。新しい式は新規作成時と同じく検証し、エラー時は何も変更しない。成功時は、その変数
    **およびそれに依存する全ての仮想変数**を再計算し、それらを表示中の曲線をその場で更新する
    （同じプロット・同じ色のまま）。
  - 削除は確認ダイアログの後、変数リストと、その変数を表示している全プロットから取り除く。
    他の仮想変数から参照されている仮想変数は削除できず、依存している変数名を一覧表示する
    （先にそちらを削除・編集してもらう。無言での連鎖削除はしない）。
  - 直接・間接を問わず自分自身を参照する式（循環定義）はエラーとする。
  - 変数リスト上で仮想変数はファイル由来の列と見分けがつくよう表示する（斜体、ツールチップに
    `名前 = 式`を表示）。
  - 編集・削除は現在のセッションに対して行われ、他のレイアウト変更と同様にビューを保存
    （同名ビューへの上書き）することで永続化される。仮想変数は常に依存順に書き出すため、
    保存したビューは正しく再読み込みできる。

#### 5.7 Δ（デルタ）解析
- 選択した変数の隣接サンプル間差分（1階差分）を計算し、時系列として表示する。

#### 5.20 ユーザー関数（2026-10-02追加、ユーザー要望）
- 仮想変数（[5.5](#55-変数間演算)）は開いているファイルの列名を直接書くので、列名が違う
  ファイルでは使い回せない。**ユーザー関数**は名前付きの引数を持つ再利用可能な式で、
  すべてのファイル・ビューで共通に使える:
  ```
  関数名:  Power_flow_by_press
  引数:    flow_lpm, press_kpa
  定数:    k = 60000            （それぞれデフォルト値付き）
  式:      flow_lpm * press_kpa / k
  説明:    流量×圧力 → 動力 [kW]
  ```
- 組み込み関数と同じように式の中で使う。定数は名前を指定して上書きしない限りデフォルト値:
  ```
  power1 = Power_flow_by_press(signal1, signal2)
  power2 = Power_flow_by_press(signal1, signal2, k=1000)
  ```
  結果は通常の仮想変数になる。
- ユーザー関数の式で使えるのは、自分の引数・定数・組み込み関数・マップ
  （[5.21](#521-マップテーブル2026-10-02追加ユーザー要望)）・他のユーザー関数。ファイルの
  列を直接参照することはできない。循環する定義はエラー。名前はPythonの識別子の規則に
  従い、組み込み関数・他のユーザー関数・マップと重複できない。
- **関数管理ウィンドウ**（ツールバー「関数」）: 一覧・追加・編集・削除。加えて
  **「信号に適用」**パネル: 関数を選び、変数一覧から信号を各引数の欄へドラッグし、
  定数を調整（デフォルト値入り）、結果の名前を付けて作成する——上の式を組み立てるだけ。
- 保存先は `cfg/parquet_analyzer/user_functions.json`（アプリ全体で共有）。
- 関数を編集すると、それを（直接または他の関数経由で）使う仮想変数をすべて再計算し、
  プロット中の線も更新する（仮想変数の編集と同じ）。仮想変数や他の関数から使われている
  関数は削除できない（使用元を一覧表示する）。
- **ビューには仮想変数の式の中の関数名だけを保存する**。ビューを開いたときにその関数が
  無ければ、その仮想変数（とそれに依存するもの）は通常のまとめ警告付きでスキップし、
  ビュー管理画面でも欠けているものとして表示する。
- 開発用の機能フラグ `user_functions`（[9](../overview.ja.md#9-非機能要件)）。
- 詳細は[detailed_specification.md 26章](#26-関数レジストリとユーザー関数2026-10-02追加ユーザー要望)。

#### 5.21 マップ（テーブル）（2026-10-02追加、ユーザー要望）
- **参照テーブル**をCSVから読み込み、式の中で関数のように使う:
  - **カーブ**（1入力）: `x, y` の2列。`name(x)` で使う。
  - **マップ**（2入力）: 1行目がX軸の値、1列目がY軸の値、中身がZの値。`name(x, y)` で使う。
  ```
  eff = map_eff(rpm, torque)
  k   = curve_temp_corr(temperature)
  ```
- **補間方法**（マップごと）: 線形（既定）/ 最近傍 / 前の値で保持（階段状）/
  3次スプライン（カーブのみ）。
- **テーブルの範囲外**（マップごと）: 端の値を保持（既定）/ 0 / 線形で延長 / NaN。
- 補間方法・範囲外の扱いは「名前 → 処理」の一覧表で持ち、後から1項目足すだけで増やせる
  ようにする。
- **マップ管理ウィンドウ**（ツールバー「マップ」）: 取り込み（CSVファイル・名前・種類・
  補間・範囲外の扱い）、一覧、設定変更、元ファイルからの再取り込み、削除、プレビュー
  （表と、カーブは線・マップはヒートマップ。[5.19](./analysis.ja.md#519-xy--xyzプロット2026-10-02追加ユーザー要望)
  の段階2ができたら3D曲面も）。
- 取り込み時にCSVを `data/parquet_analyzer/maps/` に**コピー**する。元ファイルを移動・
  削除してもマップは壊れない。「再取り込み」で元の場所のファイルを読み直す。
- （2026-10-03追加、ユーザー要望）**マップの編集**: 名前の変更と、軸の名前（X・Y・Zの表示名。
  プレビューと3D曲面の軸に出す）の設定ができる。使用中のマップの名前は変えられない（ユーザー
  関数と同じ。使用元を表示）。
- （2026-10-03追加、ユーザー要望）**値の編集**: 管理画面の表でマップの値を直接書き換えて保存できる。
  表とグラフの間の高さはドラッグで変えられる。
- （2026-10-14追加、ユーザー要望）**表の軸の固定・グラフから表のセルへ移る**: マップの表をスクロールしても、
  軸（1行目のX・1列目のY）が見えたままになる（表計算ソフトの「ウィンドウ枠の固定」と同じ）。プレビューの
  グラフ（ヒートマップのます目・カーブの点）をクリックすると、表のそのセルを選んでそこまでスクロールする。
  詳細は27.11。3Dの曲面でも格子点をクリックすると同じく表のセルへ移る（2026-10-14追加、27.12）。
- 使用中のマップは削除できない（ユーザー関数と同じ）。ビューにはマップ名だけを保存し、
  マップが無ければその仮想変数を警告付きでスキップする（ユーザー関数が無い場合と同じ）。
- 開発用の機能フラグ `maps`（[9](../overview.ja.md#9-非機能要件)）。
- 詳細は[detailed_specification.md 27章](#27-マップテーブル2026-10-02追加ユーザー要望)。

#### 5.24 移動平均の欠損の扱い（2026-10-02追加）
- `rolling_mean`は、窓の中に欠損（NaN）が1つでもあると結果も欠損になる（欠損が伝播する）。
  これを仕様として明記する。統計（5.12）は欠損を除いて計算するので、両者の違いを利用者が
  分かるようにする（式の説明・ツールチップ）。
- 欠損を無視して平均したい場合のために、**`rolling_nanmean(a, 窓幅)`**を追加する（窓の中の
  欠損でない値だけで平均する。窓の中が全部欠損ならその点は欠損）。
- 詳細は[31章](#31-移動平均の欠損の扱い2026-10-02追加)。
- **窓の位置は中心**（2026-10-04追記）: `rolling_mean`/`rolling_nanmean`は、その点の
  前後にまたがる窓（中心移動平均）で平均する。過去の値だけの移動平均ではないことを、関数の説明・
  ツールチップ・関数一覧・READMEに明記する。過去だけの窓（`mode`引数）は今は入れない。詳細は31.1。
- **過去だけの窓の移動平均**（2026-10-08追記、ユーザー判断）: `trailing_mean(a, 窓幅)`・`trailing_nanmean(a, 窓幅)`を
  足す。その点と、それより前の点だけで平均する（未来の値を使わない）。`mode`引数ではなく別の関数名にする（式の文法・
  既存の関数の引数を変えない）。欠損の扱いは`rolling_mean`/`rolling_nanmean`と同じ（伝播/除外）。データの先頭で
  過去の点が窓幅に足りない所は、**ある分だけで平均する**（`rolling_mean`の端と同じ。先頭も欠損にしない）。詳細は31.2。

#### 5.34 条件分岐（2026-10-06追加、ユーザー要望・優先度高）
- 式・ユーザー関数の本体で、条件によって値を切り替えられる（例: 回転数が3000を超えている間だけトルク、
  それ以外は0）。書き方は2通りを用意し、どちらも同じ結果になる:
  - 関数: `where(条件, 真のときの値, 偽のときの値)`（Excelの`IF`に相当）。
  - Pythonの条件式: `真のときの値 if 条件 else 偽のときの値`。
- 条件には比較（`<` `<=` `>` `>=` `==` `!=`、`0 < a < 5`のような連続した比較も可）と、
  `and` / `or` / `not`を使える。比較の結果は1（真）か0（偽）の数値なので、`(a > 0) * a`のように
  計算にも使える。
- 欠損（NaN）の判定用に`isnan(a)`（欠損なら1、それ以外は0）を足す。
- 欠損を含む比較・条件の結果は欠損（NaN）にする（「分からない」を0や1に化けさせない）。
  欠損を別の値に置き換えたいときは`where(isnan(a), 0, a)`と書く。
- すべて要素ごと（時刻ごと）に計算する。複数行のユーザー関数（途中の値に名前を付ける書き方）は
  この版には入れない（開発メモ）。
- 詳細は[43章](#43-条件分岐2026-10-06追加ユーザー要望)。

## 設計

### 6. 演算式入力（11.4）

- `ExpressionBar` にPython風の式をテキストで直接入力する（例: `A + B`, `abs(A) - sqrt(B)`,
  `rolling_mean(A, 20) ** 2`）。
- `VariablePanel` の変数をダブルクリックすると、カーソル位置に変数名が挿入される（入力補助）。
- 評価は `ast.parse` でASTを検証し、許可した演算子・関数・既知の変数名のみを許すホワイトリスト
  方式で行う（生の `eval` は使わない）。目的は悪意ある入力対策ではなく、誤入力による
  クラッシュや意図しない副作用を防ぐこと。
- **入力文字列はパース前に`unicodedata.normalize("NFKC", ...)`で正規化する**（2026-09-17
  追加。実際に発生した不具合: 日本語IMEの全角入力モードで`+`が`＋`(U+FF0B)に変換され、
  `ast.parse`が`invalid character '＋' (U+FF0B)`という生のPython構文エラーをそのまま
  `ExpressionError`経由でユーザーに表示していた）。NFKC正規化は全角英数字・全角記号
  （`＋－＊／（）`等）・全角スペース(U+3000)を対応する半角文字に変換するため、IMEの
  変換に気づかず入力した場合でも解釈できる。
  - 演算子: `+ - * / ** % //`（べき乗・剰余・切り捨て除算も対応。単項の`+ -`も可）。
  - 関数（すべて要素ごとの演算。`_ALLOWED_FUNCS`に`{名前: (期待する引数個数, 実装)}`の形で
    登録）:
    | 分類 | 関数 | 引数 |
    |---|---|---|
    | 基本 | `abs`, `sqrt` | 1 |
    | 解析 | `delta`（1階差分）, `rolling_mean`（移動平均、第2引数はウィンドウ幅。窓の中に欠損（NaN）が1つでもあると、その点の結果も欠損になる）, `rolling_nanmean`（欠損を除いた移動平均。窓の中の欠損でない点だけで平均し、端の扱いは`rolling_mean`と同じ。窓が全部欠損の点だけ欠損。31章）, `trailing_mean`/`trailing_nanmean`（過去だけの窓の移動平均。31.2） | 1 / 2 / 2 / 2 / 2 |
    | 三角関数 | `sin`, `cos`, `tan` | 1 |
    | 指数・対数 | `exp`, `log`（自然対数）, `log10` | 1 |
    | 丸め | `sign`, `floor`, `ceil`, `round` | 1 |
    | 比較・範囲 | `min`, `max`（要素ごとの比較。Python組み込みの縮約min/maxとは異なる）,
      `clip`（値, 下限, 上限） | 2 / 2 / 3 |
    | 条件 | `where`（条件, 真のときの値, 偽のときの値）, `isnan`（欠損なら1、それ以外は0。43章） | 3 / 1 |
  - `min`/`max`/`clip`は**要素ごと**の演算である点に注意（例: `max(a, 0)`はaの各サンプルを
    0未満なら0にクランプする。単一のスカラー値を返す集約関数ではない — 派生変数は
    時間軸と同じ長さの配列である必要があるため）。
  - `rolling_mean(a, window)`は畳み込み（`np.convolve`, `mode="same"`）で実装した移動平均。
    端では実際に重なった範囲だけで平均する（NaNパディングしない）ので系列全体がそのまま
    プロットできる（`core/analysis.py`）。
- **関数は引数個数も検証する**。`abs`/`sqrt`はnumpyのufuncであり2引数目は`out=`（書き込み先
  バッファ）として解釈されるため、引数個数を検証せず`sqrt(a, b)`のような式を素通りさせると
  `b`の実データを無言で書き換えてしまう（実際に発生した不具合。レビューで発見・修正。
  新しく追加した関数群にも同じ検証を適用済み）。
- 列名がPythonの識別子として不正な場合（空白・記号を含む列名など）、式中でその変数名を
  そのまま参照できない（`ast.Name`として解釈できないため）。現時点で列名のエイリアス機能は無い
  （13.4章）。
- **演算変数名が既存の列名と衝突する場合はエラーにする**（`MainWindow._on_add_derived_variable`）。
  以前は無言で上書きしていた（レビューで発見・修正）。同名の演算変数を式だけ変えて再定義する
  ことは許可している（意図的な再定義とみなす。コンテキストメニューからの編集と同じ処理を通る。
  [18章](#18-仮想変数の編集削除2026-09-30追加ユーザー要望)参照）。
- 生成された仮想変数は通常の変数と同様に `VariablePanel` に表示され、プロット・保存が可能
  （`specification.ja.md` 5.5参照）。

#### 6.1 異常な入力の扱い（2026-10-03追加、ユーザー要望「異常系のテストを強化」）

**原則: 評価・検証で起きる失敗は、すべて`ExpressionError`（またはその派生の
`UnknownFunctionError`）として外に出す。** 呼び出し側（式の入力欄、編集、ビューの読み込み
`load_view`、関数・マップ管理画面）は`ExpressionError`だけを受けて「その式だけ失敗」として扱う
ので、別の例外が漏れると、ビューの読み込みでは**1つの式のせいでビュー全体の読み込みが失敗する**。

異常な入力を実際に試して見つかった不具合（2026-10-03）と、決めた扱い:

| 入力の例 | 以前の結果 | 決めた扱い |
|---|---|---|
| `2 ** -1` | 生の`ValueError`（numpyの整数の負のべき乗） | 数値の定数はすべて**float**として評価する → `0.5` |
| `2 ** 10000`、`10 ** 400` | **黙って`0`**（int64のあふれ） | floatとして評価 → `inf`（あふれた値は無限大） |
| 400桁の整数の定数 | — | floatにできない定数は`ExpressionError` |
| `True`、`a + False` | 数値として通っていた（boolはintの派生） | `ExpressionError`（真偽値は使えない） |
| `-` を数千個重ねた式 | 生の`RecursionError` | `ExpressionError("expression too complex")`（評価中の深すぎる再帰も同じ） |
| `rolling_mean(a, b)`（窓に配列） | 生の`TypeError` | `ExpressionError`（窓は有限のスカラー） |
| `rolling_mean(a, 1.5)` | 黙って`1`に切り捨て | `ExpressionError`（窓は正の**整数**。`3.0`のように整数値のfloatは可） |
| `rolling_mean(a, 0)`・負の窓 | 生の`ValueError` | `ExpressionError` |
| `delta(1)`（スカラー） | 生の`TypeError` | スカラーは「全時刻で同じ値」とみなす → `0`（差分は0） |
| 組み込み関数・マップの実装が投げた`TypeError`/`ValueError` | そのまま漏れる | 関数名を添えて`ExpressionError`に包む（最後の砦。個別に扱いを決めたものはそちらを優先） |

意図的に**エラーにしない**もの（numpyの意味どおり。テストで現状を固定する）:

- ゼロ除算・定義域外: `a / 0` → `inf`、`0 / 0`・`log(-1)`・`sqrt(-a)` → `NaN`、`a % 0` → `NaN`。
  NaN・infは描画側が扱う（data 29.4）。評価中のnumpyの`RuntimeWarning`は出さない
  （`np.errstate(all="ignore")`で評価する。式のたびに警告が標準エラーに流れるのを避ける）。
- `clip(a, 3, 1)`（下限 > 上限）: numpyの意味（すべて上限の値）。
- `rolling_mean(a, 100)`（窓がデータより長い）: データ長に切り詰める（現状どおり）。
- 文法として許可しないもの（すべて`ExpressionError`、現状どおり）: 添字・属性・リスト/タプル・ラムダ・文字列・`None`・複素数・`@`・ビット演算・`~`・
  f文字列・`...`・代入・`;`・`*a`・空文字・空白だけ。比較・`and`/`or`/`not`・条件式は43章（2026-10-06）
  から許可する（`is`・`in`の比較は引き続き不可）。`__import__('os')`などの未知の関数は
  `UnknownFunctionError`。

- **ユーザー関数の本体の文法は保存の時点で検査する**（2026-10-03決定）。以前は`p < 1`・`p.real`・
  `p[0]`・`[p]`のように評価で使えない文法の本体も保存でき、呼んだときに初めてエラーになっていた。
  式の評価と同じ許可リスト（演算子・単項演算子・関数呼び出し・名前・数値の定数）で本体の構文木を
  検査し、外れたら`validate_user_function`が`ExpressionError`を出す（保存できない）。既に
  `user_functions.json`に保存されているそういう関数は、読み込み時の検証で1件ずつスキップされ
  警告が出る（どうせ呼べない関数なので実害は無い）。許可リストは評価と検査で1か所に置き、
  ずれないようにする。

#### 6.2 テスト計画（異常系の強化）

`tests/parquet_analyzer/`に追加する（既存のテストと重ならないもの）:

- **式（`core/expression.py`）**: 上の表の各行（以前の結果が不具合だった行は、修正前に
  失敗することを確かめる）、エラーにしないものの値、許可しない文法の網羅（パラメタライズ）、
  エラーが必ず`ExpressionError`であること（`pytest.raises(ExpressionError)`。生の
  `ValueError`等では通らない書き方にする）、全角の演算子・括弧・空白の混在、演算子の優先順位

  NaN・infを含む変数、`referenced_names`/`referenced_functions`の構文エラー時の挙動。
- **ユーザー関数（`core/functions.py`）**: 定数の上書きに`True`・`inf`・`nan`・配列・`1/0`を

### 18. 仮想変数の編集・削除（2026-09-30追加、ユーザー要望）

要件: `specification.ja.md` 5.5章。背景: 仮想変数はビュー経由で保存・再読込自体はできていた
（検証済み: 保存→開く→式を追加→保存→開くで全て保持される）が、編集・削除の手段が無かった。
また唯一の「編集」手段だった `ExpressionBar` での同名再追加は、その変数のキャッシュ配列は
置き換えるものの、(a) それを参照する他の仮想変数、(b) 既にプロット済みの曲線が**古い値のまま**
残るという不具合があった。

#### 18.1 依存関係の追跡（`core/`）

- `core/expression.py` `referenced_names(expr) -> set[str]`: 式が参照する変数名
  （`Call`の関数名を除く全ての`ast.Name`）。`evaluate_expression`と同じNFKC正規化の後に解析する。
  構文エラーは`ExpressionError`。
- `core/variable.py`:
  - `dependency_order(exprs: Mapping[str, str]) -> list[str]` — `{名前: 式}`を、各仮想変数が
    自分の参照する仮想変数より後に来る順序で返す（マッピングに無い名前＝ファイル列は無視）。
    依存関係が許す限り入力順を保つ安定ソート。循環や解析不能な式がある場合、残りは入力順で
    末尾に付ける（ここでは例外にせず、呼び出し側で通常の評価エラーとして扱わせる）。
  - `dependents_of(name, exprs) -> list[str]` — `name`に直接・間接に依存する全仮想変数を
    `dependency_order`順で返す。

#### 18.2 `MainWindow`の操作

- `edit_derived_variable(name, expression)`:
  1. `name`は既存の仮想変数であること。
  2. 循環定義チェック: `referenced_names(expression)`に`name`自身または
     `dependents_of(name)`のいずれかが含まれれば`ExpressionError`（`error.circular_definition`）。
  3. 新しい式、続いて依存する仮想変数を依存順に、新しい値で古いキャッシュを上書きした
     オーバーレイ上で評価する。全て成功するまで何も確定しない（途中で失敗すれば元の状態のまま）。
  4. 確定: `_derived`と`_raw_variables`内の`MaterializedColumn`を更新し、再計算した名前を
     表示している全時間軸プロットで`TimePlotWidget.replace_series_y(name, y)`を呼ぶ
     （常駐Y配列を差し替え、曲線・色・凡例の位置は保ったまま再描画し、カーソルラベルも更新）。
     アンカープロットが影響を受けた場合はナビゲータも更新する。
- `_on_add_derived_variable`（`ExpressionBar`経由）は、名前が既存の仮想変数であれば
  `edit_derived_variable`に委譲する。これによりバーからの再定義でも依存変数・曲線が
  古いまま残らない。
- `delete_derived_variable(name)`:
  - 他の仮想変数が`name`を直接参照していれば`ExpressionError`（`error.derived_in_use`、
    該当する変数名を列挙）。連鎖削除はしない。
  - それ以外は全時間軸プロットから系列を取り除き（FFTプロットは対象外。その系列は
    `"<name> (FFT...)"`という名前の計算済み結果で、変数への参照ではない）、
    `_derived`/`_raw_variables`/`VariablePanel`から削除し、ナビゲータを更新する。
- どちらも操作ログに記録する（`edit_derived_variable`, `delete_derived_variable`）。

#### 18.3 UI

- `VariablePanel`はどの項目が仮想変数かを把握する（`set_variables(names, derived=
  {名前: 式})`, `add_variable(name, expression=None)`, `remove_variable(name)`）。仮想変数は
  斜体で表示し、ツールチップに`名前 = 式`を出す。仮想変数を右クリックするとコンテキスト
  メニュー「式を編集...」（`editDerivedRequested(str)`）・「削除」（`deleteDerivedRequested(str)`）
  を表示する。ファイル列ではメニューを出さない。
- 編集はダイアログではなく`ExpressionBar`で行う: `MainWindow`が
  `ExpressionBar.start_edit(name, expression)`を呼ぶと、バーが編集モードになる（名前欄は
  読み取り専用、現在の式を入力済み、「追加」ボタンが「更新」に変わり、「キャンセル」ボタンを
  表示）。「更新」は「追加」と同じコールバックを通る（`_on_add_derived_variable`は既存の
  仮想変数名に対しては`edit_derived_variable`へ委譲済み）ため、`ExpressionError`時はエラーを
  表示して入力内容を保ったまま編集モードに留まり、成功時は追加モードに戻る。`cancel_edit()`
  （キャンセルボタン、または式欄でEsc）は何も変更せず追加モードに戻す。
  - ダイアログにしない理由（最初の実装はダイアログだったが、同日ユーザー指摘で変更）:
    モーダルな`QInputDialog`は変数リストの操作を塞ぐため、編集中に変数名をドラッグ・
    ダブルクリック挿入できない——これはまさに式入力バーが提供すべき入力補助（6章）である。
  - 編集中の変数が存在しなくなった場合（削除された、または`load_parquet`/`load_view`で
    仮想変数一式がリセットされた）、`MainWindow`は編集モードを解除する。
- 削除はまず`QMessageBox.question`で確認し、拒否された場合は`error.derived_in_use`を警告表示する。
- パネルを作り直す全ての箇所（`load_parquet`, `set_time_column`, `load_view`）で現在の仮想変数
  マッピングを渡し、表示区別が失われないようにする。

#### 18.4 ビュー

- `save_view_dialog`は`derived_variables`を`dependency_order`順で書き出す（追加順では不十分:
  `a`を後から定義した`b`を参照するよう編集すると、先頭要素を読み込み時に評価できない
  ファイルになってしまう）。
- `load_view`も保存済み仮想変数を`dependency_order`順で適用するため、順序の悪い古い
  ビューファイルも読み込める。
- スキーマ変更なし（`schema_version`は`"1"`のまま）。

### 26. 関数レジストリとユーザー関数（2026-10-02追加、ユーザー要望）

要件: `specification.ja.md` 5.20章。機能フラグ`user_functions`（21章）。27章（マップ）と
同じ「式で使える関数を外から足す」土台（26.1）を共有するので、26.1は27章より先に作る。

#### 26.1 関数レジストリ（`core/expression.py`の拡張）

- 現状の`_ALLOWED_FUNCS`（固定、`{名前: (引数の数, 実装)}`）を**組み込み関数**として残し、
  評価時に追加の関数を渡せるようにする:
  - `class FunctionRegistry`（`core/functions.py`、新規）: `builtins`（`_ALLOWED_FUNCS`）、
    `user_functions: Mapping[str, UserFunction]`、`maps: Mapping[str, LookupTable]`
    （27章）を束ね、`resolve(name) -> 呼び出し可能な定義 | None`と`kind(name) ->
    "builtin" | "user" | "map" | None`を持つ。名前の重複は登録側で禁止する（26.3）ので
    検索順は問題にならないが、念のため builtin → user → map の順。
  - `evaluate_expression(expr, variables, registry: FunctionRegistry | None = None)`:
    `None`なら組み込みだけ（既存の呼び出し・テストはそのまま動く）。
  - `_eval_node`の`ast.Call`分岐: `registry.resolve(name)`で探す。組み込み・マップは従来どおり
    **位置引数のみ・数が一致**（キーワード引数は`ExpressionError`のまま）。ユーザー関数だけ
    キーワード引数を許す（26.2）。未知の名前は`UnknownFunctionError(ExpressionError)`
    （`.name`に関数名を持つ。レビューで追加: UIが文言を解析せずに「関数/マップ <名前> が
    ありません」と翻訳表示できるように。i18nメッセージ`error.unknown_function`）。
- 依存関係: `referenced_functions(expr) -> set[str]`（新規、`Call`の関数名で組み込み以外の
  もの）。`referenced_names`はキーワード引数の値の中の`Name`も変数として数える（現状でも
  `ast.walk`で拾われる。定数の上書き値は数値でなければならないので、変数が入れば評価時に
  エラーになる）。
- `MainWindow`は`self._function_registry`を1つ持ち、仮想変数の評価（`evaluate_expression`を
  呼んでいる全箇所: 追加・編集（18章）・ビュー読み込み・`variable_window`等）に渡す。
  ユーザー関数・マップの一覧が変わったらレジストリの中身を差し替える。

#### 26.2 ユーザー関数の定義と評価（`core/functions.py`）

- `@dataclass UserFunction`: `name: str`, `params: list[str]`（1つ以上）,
  `constants: list[tuple[str, float]]`（順序付き、0個以上、`(名前, デフォルト値)`）,
  `expression: str`, `description: str = ""`。
- 検証`validate_user_function(fn, registry, *, replaces: str | None = None) -> None`
  （`ExpressionError`を投げる）。`replaces`は「どの既存の関数の編集・改名か」（`None`＝新規。
  新規なら同名の既存関数は重複エラー）。（レビューで変更: 当初の「同名は自分自身の編集と
  みなす」既定だと、新規作成の画面が指定を忘れたとき既存の関数を黙って上書きしてしまう。）
  検証項目:
  - `name`・各`params`・各定数名がPythonの識別子（`str.isidentifier()`かつ`keyword.iskeyword`
    でない）。引数名と定数名の重複なし。
  - `name`が組み込み関数名・他のユーザー関数名・マップ名と重複しない（編集時の自分自身は除く）。
  - （レビューで追加）本体の中の関数呼び出しを静的に検査する: 引数の数（組み込み・マップ・
    ユーザー関数の引数の数）と、キーワード引数の名前（ユーザー関数の定数名だけ。組み込み・
    マップへのキーワード引数は不可）。呼び出しの連鎖の深さが評価時の上限（32）を超える定義も
    検証で拒否する（評価して初めて失敗する定義を残さないため）。
  - `expression`が構文解析でき、`referenced_names(expression)`が`params ∪ 定数名`の部分集合
    （ファイルの列を直接参照できない。違反は`error.function_unknown_name`で名前を示す）。
  - `referenced_functions(expression)`の各名前がレジストリにある。
  - 循環なし: ユーザー関数どうしの呼び出しグラフをたどり、自分に戻ればエラー
    （`error.circular_definition`を流用）。
  - 定数のデフォルト値は有限の数値。
- 評価（`_eval_node`のユーザー関数呼び出し）:
  1. 位置引数の数 == `len(params)`（多すぎ・少なすぎはエラー。定数を位置引数で渡すことは
     できない）。
  2. キーワード引数の名前は定数名のどれか（未知の名前・重複はエラー）。値は式として評価し、
     結果がスカラー（`np.ndim(v) == 0`）かつ有限でなければエラー（`k=-1.5`や`k=2*3`は可）。
  3. 位置引数を評価して配列/スカラーを得る。
  4. 本体の式を、`{引数名: 値, 定数名: 値（上書き or デフォルト）}`だけを変数に持つ
     マッピングで評価する（同じレジストリを渡すので、本体から他の関数も呼べる）。
  - 再帰の深さは検証で防いでいるが、評価時にも深さ32で打ち切る（壊れたファイル対策）。

#### 26.3 保存（`io/user_functions.py`、新規）

- 保存先`config.PARQUET_ANALYZER_CFG_DIR / "user_functions.json"`:
  ```json
  {
    "schema_version": "1",
    "functions": [
      {
        "name": "Power_flow_by_press",
        "params": ["flow_lpm", "press_kpa"],
        "constants": [{"name": "k", "default": 60000}],
        "expression": "flow_lpm * press_kpa / k",
        "description": "流量×圧力 → 動力 [kW]"
      }
    ]
  }
  ```
- `load_user_functions() -> list[UserFunction]`: ファイルが無ければ空。JSONとして壊れている・
  形が違う場合は、**元のファイルを`user_functions.json.bad-<YYYYmmdd_HHMMSS>`に改名して退避**し、
  `logger.warning`、空として扱う（次の保存で中身が消えないように。12章の設定ファイル破損時の
  方針に合わせる）。個々の関数の検証エラーは、その関数だけ読み込まずに警告を集めて返す
  （`load_user_functions`は`(functions, warnings)`を返す）。
  - （レビューで追加）退避したことも戻り値の`warnings`に入れる（ログだけだと、利用者からは
    関数が全部消えたようにしか見えない）。
  - （レビューで追加）**読み込み自体の失敗（`OSError`: 権限・Windowsのファイルロック等）は
    退避しない**。「読めなかった」ことを呼び出し側に伝え、その間は保存を拒否する（読めて
    いないまま保存すると、無傷のファイルを空の内容で上書きしてしまうため）。
  - （レビューで追加）手で編集された異常な内容（桁数の極端な整数→`OverflowError`、極端に
    深い式→`MemoryError`等）で起動が落ちないよう、1関数ずつの検証では`ExpressionError`以外の
    例外も捕まえてその関数だけスキップする。
- `save_user_functions(functions)`: 一時ファイルに書いてから`os.replace`（途中で落ちても
  壊れない）。
- （レビューで追加）**読み込み時にスキップした関数（検証エラー・使うマップが無い等）は、元の内容の
  まま保持し、保存のたびにそのまま書き戻す**。その名前は、新しい関数やマップの取り込みの名前の
  重複チェックでも使用中として扱う。（最初の版では、スキップした関数が次の保存で黙って
  ファイルから消えていた。）

#### 26.4 管理ウィンドウ（`ui/function_manager.py`、新規）

    タブ内に表示。
- （実装時に変更）反映は`MainWindow.update_registry(user_functions=, maps=, touched=, persist=)`で行う。
  依存する仮想変数を全部計算し直して成功した場合にだけ、`persist`（ファイルへの保存）→確定の順に
  進む（保存に失敗しても何も変わらない）。保存時には他の全ユーザー関数も新しい定義で検証し直す。
- **仮想変数の計算結果の形**（レビューで追加、18章も同じ）: 追加・編集・関数/マップの変更による
  再計算のすべてで、1つの共通の処理を通して「時間軸と同じ長さの1次元のfloat64」にする。スカラー
  （例: 式`2`、引数を使わない関数）は時間軸の長さに広げた定数の系列にする。それ以外の形の違いは
  失敗として扱い、確定の前に検出して元に戻す（最初の版では確定の後に描画で例外になっていた）。
- 編集の反映: 保存で関数の式・引数・定数を変えたら、`MainWindow.on_user_functions_changed()`が
  レジストリを差し替え、その関数を（直接または他のユーザー関数経由で）使う仮想変数を
  18章の`edit_derived_variable`と同じ手順で**全部成功したら確定**の方式で再計算し、
  プロット中の曲線を`replace_series_y`で更新する。1つでも失敗したら（例: 引数の数を変えて
  既存の呼び出しが合わなくなった）保存を取り消し、失敗した仮想変数と理由を表示する。
- 名前の変更: 他から使われている関数の名前は変更できない（使用元を表示）。使われていなければ可。
- 削除: 仮想変数または他のユーザー関数から使われていれば拒否して使用元を一覧表示。
  使われていなければ確認の後に削除。
- 操作ログ: `user_function_save`, `user_function_delete`, `user_function_apply`。

#### 26.5 ビュー・ビュー管理画面

- ビューは従来どおり仮想変数の式だけを保存する（スキーマ変更なし）。関数の定義はコピーしない。
- `load_view`: 関数が無い仮想変数は評価時の`ExpressionError`で、既存の「スキップしてまとめて
  警告」の経路に乗る（8章）。依存する仮想変数・系列も同じくスキップされる。警告の中で
  「関数が無い」ことが分かるようにする（`error.unknown_function`の文言）。
- ビュー管理画面（20章）の欠けているものの印は`load_view`と同じ規則でなければならない
  （開発ルール参照）: 仮想変数の式が使う関数（`referenced_functions`）のうち、レジストリに無い
  ものがあればその仮想変数を欠けている扱いにし、推移的に依存先へ広げる。表示は
  「関数 <名前> がありません」。`ViewManagerDialog`には使える関数名の集合を渡す。
  （実装時に変更・レビューで了承）文言は関数とマップをまとめた「関数/マップ「<名前>」がありません」に
  する（無い名前は関数とマップのどちらの名前空間にも無く、どちらだったかは分からないため）。
  名前の有無に加えて、引数の数・キーワード引数の名前の静的な検査（26.2の検証と同じ規則）でも
  印を付け、`load_view`が実際にスキップするものと一致させる。

#### 26.6 テスト計画

- 評価: `Power_flow_by_press(a, b)`がデフォルト定数で正しい値、`k=1000`で上書き、
  `k=-1.5`・`k=2*3`も可、`k=a`（配列）はエラー、未知のキーワード・重複・位置引数の過不足は

  直接・間接の循環、非有限のデフォルト値がそれぞれエラー。
- 保存: 往復、ファイル無し、壊れたJSONの退避（`.bad-*`ができて元の内容が残る）、1つだけ
  不正な関数があっても他は読み込まれ警告が返る、書き込みが一時ファイル経由。

### 27. マップ（テーブル）（2026-10-02追加、ユーザー要望）

要件: `specification.ja.md` 5.21章。機能フラグ`maps`（21章）。26.1のレジストリを使う。

#### 27.1 データと補間（`core/maps.py`、新規）

- `@dataclass LookupTable`: `name`, `kind: "curve" | "map"`, `x: np.ndarray`（狭義単調増加）,
  `y: np.ndarray`（curve: 出力値、`len(x)`個 / map: Y軸の値、狭義単調増加）,
  `z: np.ndarray | None`（map: 形`(len(y), len(x))`）, `interpolation: str`,
  `extrapolation: str`。
- 呼び出し: curveは引数1つ`table(x)`、mapは引数2つ`table(x, y)`。引数は配列またはスカラー
  （ブロードキャスト）。戻り値は入力と同じ形のfloat64配列。入力のNaNは出力もNaN。
- **補間方法の一覧**（`INTERPOLATIONS: dict[str, InterpolationSpec]`、`kinds`でcurve/map
  どちらに使えるかを持つ）。後から1項目足すだけで増やせる形（6章の`_ALLOWED_FUNCS`と同じ考え方）:
  | 名前 | curve | map | 内容 |
  |---|---|---|---|
  | `linear`（既定） | ○ | ○（双線形） | 隣接点の線形補間 |
  | `nearest` | ○ | ○ | 最も近い格子点の値 |
  | `previous` | ○ | ○ | 各軸で「その値以下の最大の格子点」の値（階段状） |
  | `spline` | ○ | × | 自然3次スプライン |
  - `spline`はscipyを使わずnumpyで実装する（三重対角の連立方程式。scipyは`convert`
    依存グループにしか無く、メインの依存に足すと配布物が大きくなるため）。点が3つ未満の
    カーブでは`linear`にフォールバック（取り込み時に警告）。
- **範囲外の扱いの一覧**（`EXTRAPOLATIONS`）、各軸ごとに適用:
  | 名前 | 内容 |
  |---|---|
  | `clamp`（既定） | 端の値（入力を軸の範囲に丸めてから補間） |
  | `zero` | 範囲外なら0 |
  | `linear` | 端の傾きで延長: 線形・双線形補間では端の2点（mapでは端の格子）の傾き、`spline`では端の**接線**の傾き（自然スプラインは端で2階微分0なので、接線で延長すると滑らかにつながる。レビューで変更: 当初の「端の2点を結ぶ傾き」では表の端で折れ曲がる）。`nearest`・`previous`では端の値 |
  | `nan` | 範囲外ならNaN |
  - `previous`と`linear`外挿の組み合わせなど、意味の薄い組み合わせも禁止はしない
    （`previous`は範囲外で端の値になる、と定義しておく）。
- 実装はベクトル化（`np.searchsorted`）で、1,000万点の入力でも1回の呼び出しで処理できること。
- `nearest`で2つの格子点のちょうど中間の値は、大きい方の格子点の値にする。
- 入力が±infのとき、`linear`外挿では計算どおりの±infまたはNaN（例外にはしない）。

#### 27.2 CSVの読み込み（`io/maps.py`、新規）

- 文字コード: `utf-8-sig`で読み、失敗したら`cp932`（Excelで保存した日本語CSV対策）。
  区切りはカンマ。空行・前後の空白は無視。
- **カーブ**: 2列。1行目が数値でなければ見出しとして読み飛ばす。各行`x, y`。
- **マップ**: 1行目 = [左上のセル（空または任意の文字）, X軸の値…]、2行目以降 =
  [Y軸の値, Zの値…]。行ごとの列数が1行目と同じでなければエラー（行番号を示す）。
- 種類は取り込みダイアログで選ぶ（既定は自動判定: 列が2つならカーブ、3つ以上で左上のセルが
  空または数値でなければマップ）。**3列以上で左上のセルが数値の場合は自動判定できないので
  エラー**にし、ダイアログでカーブ/マップを選んでもらう（レビューで明確化: 数値だけの
  `x, y1, y2`のファイルが黙って変なマップとして読まれるのを防ぐ）。
- 1行目を見出しとして読み飛ばすのは、**数値として読めるセルが1つも無い**ときだけ。一部だけ
  数値でない行は、通常どおり行・列番号付きのエラーにする（レビューで判明: 1つでも数値でない
  セルがあると見出し扱いにしていたため、最初のデータ点が黙って消えていた）。
- 検証（エラーは`MapError(ValueError)`、行・列番号付きのメッセージ）: 数値に変換できない
  セル、軸に重複・非単調（**昇順でない場合はエラー**。並べ替えはしない——取り違えに
  気付けるように）、軸・Zに非有限値、カーブで2点未満、マップで各軸2点未満。
- 戻り値は`LookupTable`（`interpolation`/`extrapolation`は取り込みダイアログの値）。

#### 27.3 保存（`data/parquet_analyzer/maps/`）

- `config.PARQUET_ANALYZER_DATA_DIR / "maps"`。取り込むと:
  - `<name>.csv` — 元のCSVファイルを**そのままコピー**（`shutil.copy2`）。
  - `<name>.json` — `{"schema_version": "1", "name", "kind", "interpolation",
    "extrapolation", "source_path"（元ファイルの絶対パス、再取り込み用・参考情報）,
    "imported_at"（ISO 8601）}`。
- `list_maps()`, `load_map(name) -> LookupTable`（コピーしたCSVを27.2で読み直す）,
  `save_map_settings(name, interpolation, extrapolation)`, `reimport_map(name)`（`source_path`
  から読み直してCSVを上書き。元ファイルが無ければエラー）, `delete_map(name)`（両ファイル削除）。
- 名前の検証はビュー名と同じ方式（`Path(name).name == name`）に加え、Pythonの識別子であること
  （式から呼ぶため）、組み込み関数・ユーザー関数・他のマップと重複しないこと。
  - （レビューで追加）検証は取り込み時だけでなく、**ファイルのパスを作る所**（読み込み・設定
    変更・再取り込み・削除の全経路）で行う（取り込み時だけだと`delete_map("../x")`で
    `maps/`の外のファイルを消せてしまった）。`list_maps`/全マップの読み込みでは、名前として
    不正なファイル・組み込み関数と同名のファイルは警告して飛ばす（ファイルは消さない）。
- 起動時（`MainWindow.__init__`）に全マップを読み込んでレジストリに登録する。読めないマップは
  登録せず、まとめて1回警告（ファイルは消さない）。

#### 27.4 管理ウィンドウ（`ui/map_manager.py`、新規）

- ツールバー「マップ」（ショートカット設定可能`maps`、既定なし）。非モーダル、同時に1つ。
- 左: マップ一覧（名前・種類）。右: 選択中のマップの設定（補間・範囲外の扱い、コンボ。
  curveでだけ使える`spline`はmapでは選べない）と、元ファイル・取り込み日時、プレビュー:
  - 表（`QTableWidget`、読み取り専用）。
  - （レビューで追加）マップの元の格子のヒートマップは、**実際の（不等間隔のこともある）軸の値の
    位置**に描く（`PColorMeshItem`、隣り合う格子点の中点をセルの境界にする）。補間結果は元の格子の
    横に2つ目のヒートマップとして並べる（重ねない）。3Dの切替は25.3ができてから。
  - グラフ: curveは線（格子点に点）、mapはヒートマップ（`ImageItem`＋カラーバー、軸は実際の

    だけと検証済みなので、`set_surface`のNaNは汎用APIとしての扱い（マップでは起きない）。
  - さらに、選択中の補間・範囲外の扱いで計算した**補間結果の曲線/面**を重ねて表示し、
    設定の違いを目で確かめられるようにする（curve: 範囲の前後10%まで広げた細かい点で計算）。
- ボタン: 「取り込み…」（ファイル選択 → 名前・種類・補間・範囲外の扱いのダイアログ。
  名前の既定はファイル名を識別子に直したもの）、「再取り込み」、「削除」。
- 設定変更・再取り込みの反映: 26.4と同じく、そのマップを使う仮想変数を全部再計算して
  成功したら確定、失敗したら取り消し。
- 削除: 仮想変数・ユーザー関数から使われていれば拒否して使用元を表示。
- 操作ログ: `map_import`, `map_reimport`, `map_settings`, `map_delete`。

#### 27.7 マップの編集（名前・軸の名前）（2026-10-03追加、ユーザー要望）

- 管理ウィンドウのボタン「編集…」（一覧のダブルクリックでも）で、名前と軸の名前（X・Y・Z。
  カーブはX・Y）のダイアログを開く。
- 名前の変更: 27.3と同じ検証（識別子・組み込み関数/ユーザー関数/他のマップと重複しない）。
  **仮想変数・ユーザー関数から使われていれば拒否**して使用元を表示する（26章のユーザー関数の改名と

  - 保存済みのビューに古い名前が残っていても書き換えない（読み込むと27.5どおりスキップ＋警告）。
  - 途中で失敗したら元の状態に戻す（ファイル名の変更は2つともできたときだけ確定）。

#### 27.8 マップの値の編集・プレビューの高さ（2026-10-03追加、ユーザー要望）

- **値の編集**: 管理ウィンドウの表（`QTableWidget`）を編集可能にし、セルの値（ZとX・Y軸の値。カーブは
  x・y）を書き換えられる。編集中は「保存」「元に戻す」ボタンを有効にし、変更されたセルは色で示す。
  - 検証（保存時）: すべて有限の数値、軸は狭義単調増加（27.2と同じ規則。違反は行・列を示して保存しない）。
  - 保存: 保存しているCSVのコピー（27.3の`<name>.csv`）を27.2の形式で書き直し、JSONに`edited_at`
    （ISO 8601）を追加する。26.4と同じく、そのマップを使う仮想変数を全部再計算して、成功したら確定、
    失敗したら元に戻す（CSVも元に戻す）。プレビューを更新する。
  - 「元に戻す」: 保存前の編集を捨てて表を読み直す。編集中に別のマップを選ぶ・ウィンドウを閉じると、
    保存するか確認する。
  - 再取り込みは編集を上書きするので、`edited_at`があれば確認してから行う。
  - 行・列の追加・削除はこの版では対象外。
- **プレビューの高さ**: 表とグラフ（ヒートマップ・曲線）の間を`QSplitter`にして、ドラッグで高さを
  変えられる。比率は設定に保存（`map_manager_splitter`）。
- 操作ログ: `map_values_edit`（保存時。変更したセルの数）、`map_values_revert`。
- テスト: セルを編集して保存するとCSVとレジストリが変わり、仮想変数の値が変わる。不正な値・降順の軸は
  保存されない（表示は残る）。再計算の失敗で元に戻る。「元に戻す」。編集中の切替・閉じるで確認が出る。
  再取り込みで確認が出る。スプリッタの比率の保存と復元。

#### 27.9 編集中の変更前・変更後の表示と3D（2026-10-03追加、ユーザーの実機確認から）

- **変更前・変更後**: 表に未保存の変更があるあいだ、グラフの2枚（今は「表」と「補間結果」）を
  「**変更前**」（保存済みの値）と「**変更後**」（編集中の値。セルを書き換えるたびに更新）にする。
  同じ色の範囲（両方の値を合わせた最小・最大）で描き、違いが分かるようにする。保存・元に戻すと
  元の2枚に戻る。カーブは1枚のグラフに変更前（細い灰色）と変更後（太い色）を重ねる。
  変更後の値が不正（数値でない・軸が昇順でない）なあいだは、変更後を描かず理由を出す。
- **3Dへの切替**: マップ管理画面の「3D」切替（25.5で軸名付き）が、編集中は変更前・変更後の
  2つの3D曲面（`Xyz3DView`を2つ横に並べる）になる。2つのカメラは連動させる（片方を回すと
  もう片方も同じ視点。ホーム・XY・YZ・ZXも両方に効く）。Zの範囲（正規化）は両方の値を合わせて
  決める（同じ高さが同じ値になるように）。ヒートマップ⇔3Dの切替は編集中もいつでもできる。
- 操作ログは追加なし（27.8の`map_values_edit`/`map_values_revert`のまま）。
- テスト: 編集すると変更前・変更後のグラフになり、保存・元に戻すで戻る。色の範囲が両方を含む。
  不正な値のあいだは変更後を描かない。3Dで2つの曲面になり、カメラが連動する（片方の
  `setCameraPosition`がもう片方に反映）。実機で画像を確認する。

#### 27.10 空のセルのあるマップ・カーブ（2026-10-06追加、analysis 44章から）

背景: 実測から作ったマップ（analysis 44章）で「空のます目は空のまま」を選んだとき、そのまま登録して式で使える
ようにする。決定（2026-10-06、ユーザー）: 空きの扱いは選べる（既定は埋める）。

- **CSV**（27.2）: マップのZ・カーブのyで、**空のセル**（空文字・空白だけ）を欠損（NaN）として読む。軸の値は
  今までどおり空・非有限を許さない。`nan`・`NaN`と書かれたセルも欠損として読む（書き出しは空のセル）。
  `inf`は今までどおりエラー。有限の値が1つも無いマップ・カーブはエラー。
  取り込み時に「空のセルがn個あります（そこにかかる値は欠損になります）」と1回警告する（取り込みは続ける）。
- **補間**（27.1）:
  - `linear`（双線形・線形）: 計算に使う格子点（重みが0でないもの）のどれかが欠損なら、結果は欠損。
    格子点ちょうどの入力は、その格子点の値（欠損なら欠損）。
  - `nearest`・`previous`: 選ばれた格子点の値（欠損なら欠損）。
  - `spline`（カーブ）: 欠損を含むカーブでは選べない（取り込み・設定変更でエラーにし、`linear`を案内する）。
  - 範囲外の扱い: `clamp`・`linear`外挿は端の格子点・端の傾きを使う。それが欠損なら欠損。`zero`・`nan`は
    今までどおり。
- **管理画面**（27.4・27.8・27.9）: 表で空のセルは空欄で表示し、編集で空にできる（保存時の検証で「有限の数値か
  空」を許す。軸は今までどおり）。ヒートマップ・3D曲面のプレビューは空のセルを描かない（44.3と同じ描き方）。
  曲線は欠損の点でつながない。
- **式の評価**（26・36.8）: 欠損は普通の値と同じく式を伝わるだけなので、評価の側の変更は無い。
- テスト: 空のセルのCSVの読み込み（マップ・カーブ、`nan`の表記、全部空がエラー、軸の空はエラー、警告が1回）、
  各補間・範囲外の扱いで欠損が伝わる範囲（双線形で欠損の格子点に接する4つのます目だけが欠損になり、それ以外は
  今までと同じ値）、`spline`の拒否、表で空にして保存→CSVが空のセル→読み直して同じ、プレビューが例外なく描ける、
  既存のマップ（空のセル無し）の値が変わらない（回帰）。

#### 27.11 表の軸の固定・グラフのクリックで表のセルへ移る（2026-10-14追加、ユーザー要望。開発メモの項目42）

**(1) 表の1行目・1列目の固定（マップだけ）**

- 今の表（27.8の配置）: 1行目＝X軸の値、1列目＝Y軸の値、左上＝`<Y名> \ <X名>`の角のセル。Qtの見出しは隠している。

  共有する`QTableView`を3つ重ねる**（上端の行・左端の列・左上の角）。

  マップ⇔カーブで選択を切り替えたとき、重ねた表が残らない・出しっぱなしにならないこと。
- 表の行・列が1画面に収まるときも固定は出したままでよい（見た目は今と同じになる）。

### 31. 移動平均の欠損の扱い（2026-10-02追加）

要件: 5.24。背景: `core/analysis.py`の`rolling_mean`は`np.convolve`で計算しており、窓に欠損が
あると結果が欠損になる。統計（`basic_stats`）は欠損を除外するので挙動がそろっていないが、
どちらの挙動かは仕様に書かれていなかった（外部レビュー1の#5）。

- 6章の関数表の`rolling_mean`の説明に「窓の中に欠損があると結果も欠損」を追記する。
- `core/analysis.py`に`rolling_nanmean(y, window)`を追加: 欠損を0として和を、欠損でない点の数を
  別に畳み込み（`rolling_mean`と同じ端の扱い）、`和 / 個数`（個数0の点は欠損）。
- `_ALLOWED_FUNCS`に`"rolling_nanmean": (2, rolling_nanmean)`を1行足す（関数レジストリ26.1の
  組み込みとしても使える）。窓幅の検査は`rolling_mean`と同じ。
- 式入力欄の関数の説明（ツールチップ・ドキュメント）に、両者の違いを書く。
- テスト: 欠損の無いデータでは`rolling_mean`と一致、途中・先頭・末尾の欠損、全部欠損の窓、
  窓幅1、窓幅がデータより長い、整数の配列。

#### 31.1 窓の位置（中心）の明記（2026-10-04追加）

背景: 実装は`np.convolve(mode="same")`による**中心**移動平均だが、関数の説明・ツールチップ・README
には「移動平均」としか書いておらず、過去の値だけの移動平均と読み違えるおそれがある（公開版の利用者）。

- 窓の範囲: 窓幅nのとき、出力iは入力`y[i - ⌊n/2⌋]`〜`y[i + ⌈n/2⌉ - 1]`の平均（nが奇数なら前後に
  (n-1)/2点ずつ、偶数なら前にn/2点・後にn/2-1点）。端では窓をデータのある範囲に縮める（今のまま）。
- 書き直す所（英日両方）: `ui/i18n.py`の式の関数の説明（`rolling_mean`/`rolling_nanmean`）・関数一覧の
  説明（`fnref.desc.rolling_mean`/`fnref.desc.rolling_nanmean`）、README（英・日）の関数の説明。
  「中心移動平均（その点の前後の窓）」と、偶数のときの偏りを短く書く。
- 計算は変えない。`mode`引数（過去だけの窓）は今は入れない（必要になったら別に仕様化）。
- テスト: 偶数・奇数の窓で、1点だけ1の入力に対する出力の位置が上の範囲どおり（窓の位置を固定する
  回帰テスト）。

#### 31.2 過去だけの窓の移動平均`trailing_mean`/`trailing_nanmean`（2026-10-08追加、開発メモの項目28）

要件: 5.24の追記。背景: 中心移動平均（31.1）は未来の値も使うので、「その時点までに分かっている値の平均」
（制御・リアルタイム処理の再現）には使えない。過去だけの窓を`mode`引数で切り替える案もあったが、**別の関数名**にする
（2026-10-08、ユーザー判断。式の文法・既存関数の引数の数を変えない、関数一覧で別の項目として探せる）。

- 窓の範囲: 窓幅nのとき、出力iは入力`y[max(0, i-n+1)]`〜`y[i]`の平均（その点を含む過去n点）。先頭（i < n-1）は
  ある分だけで平均する（`rolling_mean`の端と同じ。欠損にしない、2026-10-08ユーザー判断）。窓幅がデータより長い
  ときは長さに切り詰める（結果は累積平均と同じ）。
- `core/analysis.py`に`trailing_mean(y, window)`・`trailing_nanmean(y, window)`を足す。計算は累積和の差（`O(n)`）でも
  畳み込みでもよいが、**窓の中のNaNの扱い**が次のとおりであること:
  - `trailing_mean`: 窓に1つでも欠損があれば結果は欠損（`rolling_mean`と同じ）。累積和で計算する場合は、NaNが
    以後の全点に伝わらないよう、値は欠損を0にした累積和、欠損の数は別の累積和で数え、窓の欠損の数が1以上の点を欠損にする。
  - `trailing_nanmean`: 窓の欠損でない点だけで平均、窓が全部欠損の点だけ欠損（`rolling_nanmean`と同じ）。
  - ±Infは`rolling_mean`と同じくそのまま計算に入る（窓にInfがあれば結果はInfかNaN）。累積和にInfが入ると以後の差が
    NaNになるので、累積和で計算するなら非有限値も欠損と同じく別に扱うか、畳み込み（`np.convolve(y, ones(n))[:len(y)]`
    ＝過去n点の和、個数は`min(i+1, n)`）で計算する。**素直な実装（各点で窓を切り出して`np.mean`/`np.nanmean`）と一致**
    することをテストで確かめる。
  - 長さ0の入力は長さ0を返す。整数の配列はfloatの結果。
- 窓幅の検査は`rolling_mean`と同じ（6.1の表: 有限のスカラー・正の整数・`3.0`は可、ほかは`ExpressionError`）。
  共通の検査があればそれを通す。
- 登録: `_ALLOWED_FUNCS`に2行（引数2）、`_FUNC_MARGINS`に**`(n-1, 0)`**（前にn-1行、後ろに0行。data 36.6 Cの
  `DerivedColumn`が窓読み込みで正しく計算できるように）。`_rolling_margin`と同じく、窓幅が定数でなければ`None`（全件計算）。
- 説明（英日）: `ui/i18n.py`の式の関数の説明・関数一覧（`fnref.desc.*`・使用例`fnref.example.*`等、既存の`rolling_*`と
  同じキーの組）、分類は「解析」、README（英・日）の関数の説明。`rolling_*`の説明にも「過去だけの窓は`trailing_mean`」と
  一言添える。
- 13.4（開発メモ）の「`rolling_mean`は時間ベースの窓を指定できない」は今回の対象外（サンプル数の窓のまま）。

**テスト計画**:

### 43. 条件分岐（2026-10-06追加、ユーザー要望）

要件: 5.34。背景: 「条件を満たす間だけ値を使う」計算が書けず、`clip`・`sign`・`max`を組み合わせる
回避策しか無かった。機能フラグは使わない（文法を足すだけで、今まで書けた式の結果は変わらないため）。

#### 43.1 文法と値（`core/expression.py`）

真偽は**float64の1.0 / 0.0**で表す（boolの配列は作らない。仮想変数は常にfloat64、18/26章）。
条件として値を受け取るときは「0以外が真、0が偽、NaNは不明」とする。

| 文法（AST） | 結果 | 欠損（NaN）の扱い |
|---|---|---|
| 比較`a < b`等（`ast.Compare`。`Lt LtE Gt GtE Eq NotEq`のみ） | 1.0 / 0.0 | どちらかがNaNなら**NaN**（numpyの比較はFalseを返すので、明示的にNaNにする） |
| 連続した比較`a < b < c` | `(a < b) and (b < c)`と同じ（`b`は1回だけ評価） | 同上 |
| `x and y`・`x or y`（`ast.BoolOp`、3つ以上も可） | 1.0 / 0.0（Pythonのような「オペランドそのものを返す」動きはしない） | **3値論理**（43.5で変更、2026-10-07）: `or`はどれかが真なら1.0、`and`はどれかが偽なら0.0。それで決まらずNaNがあればNaN |
| `not x`（`ast.UnaryOp`の`Not`） | 1.0 / 0.0 | NaNならNaN |
| `a if c else b`（`ast.IfExp`）・`where(c, a, b)` | `c`が真の要素は`a`、偽は`b` | `c`がNaNの要素はNaN（`a`・`b`のNaNはそのまま） |
| `isnan(a)` | 1.0 / 0.0 | NaNを受けても1.0（NaNにはならない）。±infは0.0 |

- **±inf**は普通の数として比較する（`inf > 1`は1.0）。0以外なので条件としては真。
- **両方の枝を全部計算する**（要素ごとの短絡はしない）: `where(x > 0, log(x), 0)`は負の`x`でも`log`を
  計算するが、評価は`np.errstate(all="ignore")`の中なので警告は出ず、選ばれない側の値は捨てられる（6.1と同じ）。
- **スカラーと配列**: 条件・各枝がスカラーでも配列でもよい（numpyの放送）。全部スカラーならスカラー
  （`where(1 > 0, 2, 3)`は`2.0`）。仮想変数としての長さそろえは既存の補助関数（18章）が行う。
- **`True`/`False`の定数は今までどおり不可**（6.1）。真偽が要るときは`1`/`0`を書く。
- `is` / `is not` / `in` / `not in`は`ExpressionError`（数値の比較ではないため）。
- `where`・`isnan`は組み込み関数として`_ALLOWED_FUNCS`に登録する（引数の数は3 / 1、6.1の検証が効く）。
  同名のユーザー関数・マップは既存の規則（26.2の重複禁止）で作れなくなる。**既に`where`・`isnan`という
  名前のユーザー関数・マップが保存されている場合**は、読み込み時の検証で1件ずつスキップされ警告が出る
  （26.3・27.3の既存の動き）。ビューの式がそれを使っていれば、その仮想変数がスキップされる。
- 許可リストは評価（`_eval_node`）・構文の検査（`check_allowed_syntax`、ユーザー関数の保存時の検査にも
  使われる）・範囲の余白（`_margin`）の3か所で**同じ集合**を使う（ずれるとユーザー関数を保存できるのに
  呼べない、などが起きる。6.1の方針）。

#### 43.5 レビューで判明した修正（2026-10-07、ユーザー了承）

マージ後のレビュー（2026-10-07）で判明。

- **`and`/`or`を3値論理にする**（43.1の表を変更）。要素ごとに:
  - `or`: どれかのオペランドが真（0以外の有限値・±inf）なら1.0。そうでなく、どれかがNaNならNaN。それ以外は0.0。
  - `and`: どれかが偽（0）なら0.0。そうでなく、どれかがNaNならNaN。それ以外は1.0。
  - 理由: 元の「どれかがNaNならNaN」では、`where(isnan(x) or x < 0, 0, x)`のようにNaNを置き換える自然な書き方が
    肝心のNaNの行で効かない（`isnan`を足した意味が無くなる）。`not`・比較・条件のNaNの扱いは変えない。
- **比較・`and`/`or`の中で起きたエラーの種類を変えない**: 今はオペランドの評価が`try/except (TypeError,
  ValueError)`の中にあり、`UnknownFunctionError`（`ValueError`の子）が「comparison: …」「and: …」の付いた
  ただの`ExpressionError`に変わる（`1 < foo(x)`、`x > 0 and foo(x)`。`foo(x) < 1`なら変わらないので順で結果が違う）。
  そのため式の入力・ビューの読み込み（`main_window`）で「不明な関数」の訳した文が出ない。オペランドは`try`の
  外で評価し（`IfExp`と同じ）、`try`は配列どうしの演算だけを囲む。
- テスト: (1) 3値論理の真理値表（真/偽/NaNの全組み合わせ、2項・3項、配列とスカラー）、
  (2) `where(isnan(x) or x < 0, 0, x)`がNaNの行で0、(3) `1 < foo(x)`・`x > 0 and foo(x)`・`not foo(x)`が
  `UnknownFunctionError`、`x < (1 < y)`（未知の変数）のメッセージに「comparison:」が重ならない、
  (4) 式の入力欄で`1 < foo(x)`を入れると「不明な関数」の訳した文が出る。(1)(2)(3)は直す前に失敗すること。
